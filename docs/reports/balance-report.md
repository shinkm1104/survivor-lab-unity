# 클래스 밸런스 측정 보고서

측정일 2026-11-02 · 대상 `balance.json` v2 · 총 984판

> 이 보고서 다음에 웨이브 시스템(`balance.json` v3)을 넣었습니다. 바뀐 결과는 아래 [웨이브 시스템 적용 후](#웨이브-시스템-적용-후-v3) 절에 있습니다.

## 한 줄 요약

공명술사와 유도술사는 너무 쉽고, 충격술사는 AI가 플레이하면 한 판도 못 깹니다. 그리고 클래스와 상관없이 **계속 도망만 다니면 전부 이깁니다.** 실제로 위험한 시간은 시작 후 60초뿐입니다.

## 무엇을 어떻게 돌렸나

게임과 똑같은 `Simulation`을 Unity 배치 모드에서 0.05초 단위로 돌렸습니다. 클래스마다 시드 40개(1000~1039)를 썼고, 아래 조합마다 한 번씩 돌렸습니다. 게임 안의 WATCH AI가 쓰는 시드 90210도 따로 한 번씩 돌렸습니다.

| 이동 | 설명 |
|---|---|
| `q` | 게임 WATCH AI와 같은 Q-learning 정책 (`initial-policy-v2.json`), 0.1초마다 판단 |
| `kite` | 비교용 스크립트 봇. 주변 적 반대 방향으로 원을 그리며 피하고, 한가할 때 경험치를 줍습니다 |
| `still` | 처음 자리에서 움직이지 않음 |

| 보상 선택 | 설명 |
|---|---|
| `learned` | 게임 기본값인 REINFORCE 학습 정책 (`reward-policy.json`) |
| `rule` | 게임의 규칙 기반 선택 (`RewardAdvisor`) |
| `random` | 무작위 선택 (비교용) |

## 발견한 문제

### 1. 공명술사·유도술사는 가만히 있어도 이긴다

움직이지 않아도 공명술사 40/40, 유도술사 39/40으로 생존했습니다. 유도술사는 게임 기본 AI로 돌렸을 때 이긴 판의 최저 체력 평균이 98%였습니다. 사실상 한 대도 안 맞는다는 뜻입니다. 두 클래스 모두 생성되는 적의 98% 이상을 처치했습니다.

### 2. 충격술사는 AI가 등 뒤를 때린다

충격술사는 **마지막으로 이동한 방향**으로 충격파를 쏩니다. 그런데 Q 정책은 적에게서 멀어지는 쪽으로 움직이기 때문에 공격이 계속 반대쪽으로 나갑니다.

| 충격술사 | 빗나간 충격파 | 가장 가까운 적을 등진 충격파 |
|---|---:|---:|
| q (게임 AI) | 57% | 67% |
| still (안 움직임) | 18% | 22% |
| kite (도망만) | 97% | 68% |

그래서 가만히 서 있는 쪽(32.5%)이 게임 AI(0%)보다 승률이 높습니다. 클래스 성능보다는 공격 방식과 AI 이동 정책이 맞지 않는 문제에 가깝습니다. 그래도 서 있는 쪽 승률이 32.5%에 그치니 다른 클래스보다 약한 것도 사실입니다.

### 3. 도망만 다니면 모든 클래스가 이긴다

`kite` 봇은 160판 모두 생존했습니다. 자동 조준인 유도술사를 빼면 적을 4~5마리만 잡고 레벨 2~3에 머문 채로 이겼습니다. 적 속도가 1.6이고 플레이어 속도가 5라서, 계속 움직이기만 하면 적이 따라잡지 못합니다. 성장이나 보상 선택이 생존에 필요하지 않은 구조입니다.

### 4. 시작 60초만 넘기면 끝까지 산다

전체 사망 288건 중 246건(85%)이 60초 안에 일어났고, 90초 이후 사망은 9건뿐입니다. 가장 늦은 사망은 177초였습니다. 적 체력(12)과 생성 간격(0.65초)이 끝까지 그대로라서, 레벨 7 전후로 화력이 생성 속도를 넘어서면 그다음부터는 위협이 없습니다. 공명술사·유도술사·각인술사의 평균 DPS가 모두 약 18로 같게 나오는데, 이건 화력의 한계가 아니라 **초당 생성되는 적 체력 총량(약 18.5)** 에 막힌 값입니다.

### 5. 각인술사는 보상 선택에 따라 결과가 갈린다

같은 이동 정책인데 학습 정책을 쓰면 82.5%, 규칙 기반을 쓰면 5%입니다.

- 학습 정책은 처음 6번의 선택 중 57%를 **최대 체력**에 썼습니다.
- 규칙 기반은 처음 6번을 대부분 **시전 속도·주문 피해**에 썼습니다(최대 체력 17%).

각인술사 AI는 받는 피해가 609로 다른 클래스보다 훨씬 많습니다. 체력을 먼저 올리지 않으면 초반을 못 버팁니다.

### 6. AI 이동 정책이 벽에 붙는다

Q 정책 사망 220건 중 114건이 벽에서 2칸 이내에서 일어났습니다. 각인술사 AI는 플레이 시간의 35%를 벽 근처에서 보냈습니다. 아래 재현 사례 3건도 모두 남쪽 벽(y = -32)에서 끝났습니다.

### 7. WATCH AI는 항상 같은 판을 보여준다

`GameApp.Begin`이 시드를 90210으로 고정합니다. 그래서 게임을 켜고 충격술사로 WATCH AI를 처음 누르면 36.4초에 아래 재현 사례 A와 같은 방식으로 죽습니다(같은 실행 안에서 다시 누르면 AI의 동점 처리 난수가 달라져 조금 다를 수 있습니다). 직접 플레이할 때도 적 생성 위치가 매번 같습니다.

## 고칠 만한 것

이 보고서를 쓸 때 제안한 목록입니다. 1·2번은 아래 웨이브 시스템으로 적용했고, 나머지는 아직입니다.

1. **시간이 지날수록 적을 강하게.** 60초마다 적 체력·속도·생성량을 올리면 4번 문제(60초 이후 위협 없음)와 1번 문제가 같이 줄어듭니다.
2. **도망이 공짜가 되지 않게.** 적 기본 속도를 올리거나 빠른 적(돌진형 등)을 섞어야 3번 문제가 해결됩니다.
3. **충격술사 조준 변경.** 가장 가까운 적 쪽으로 자동 조준하거나 조준 방향을 이동과 분리하면 AI와 사람 모두 덜 헷갈립니다. 지금 방식을 유지한다면 Q 정책 관측값에 바라보는 방향을 넣고 다시 학습해야 합니다.
4. **이동 정책에 벽 페널티.** 학습 보상에 벽 근처 감점을 넣거나 벽 거리 구간을 더 세밀하게 나누면 6번 문제가 줄어듭니다.
5. **규칙 기반 보상에서 각인술사 최대 체력 점수 상향.** 지금 `RewardAdvisor`는 체력이 40% 미만일 때만 최대 체력을 우선합니다.
6. **WATCH AI 시드 무작위화.** 매번 다른 판을 보여주도록 바꾸면 됩니다.

수치를 바꾼 뒤에는 `balance.cmd`를 다시 돌려 이 표와 비교하면 됩니다. 이동 정책은 지금 수치 기준으로 학습된 것이라, 적 속도나 체력을 바꾸면 다시 학습해야 할 수 있습니다.

## 웨이브 시스템 적용 후 (v3)

마법주문팀(The Spell Brigade)의 난이도 구조를 참고해서 아래를 넣었습니다. 수치는 5분짜리 우리 게임에 맞춰 새로 정했습니다.

- 30초마다 바뀌는 웨이브 10개. 웨이브마다 최소 동시 적 수(8 → 72), 생성 간격과 수, 적 체력(×1 → ×4.2), 속도(×1 → ×2.06), 접촉 피해(×1 → ×2.5), 처치 경험치(4 → 2)가 정해져 있습니다. 적을 빨리 잡아도 최소 수만큼 다시 채웁니다.
- 이동 차단 생성: 웨이브마다 0~60% 확률로 플레이어가 움직이는 방향 앞쪽(±35°)에 적을 소환합니다.
- 빠른 적: 일반 적의 2.1배 속도, 체력 절반. 6웨이브부터는 플레이어보다 빠릅니다.
- 적 줄 이벤트: 100·165·225·265초에 빈틈 하나(3.2 → 2.4칸)가 있는 적 줄이 지나갑니다.
- 20칸 넘게 떨어진 적은 경험치 없이 정리합니다. 이게 없으면 적 상한이 뒤따라오는 적으로 차서 새 적이 생성되지 않았습니다.
- 물약은 20마리에서 50마리마다로 줄였고, 공명술사 피해는 5.07에서 4.4로 낮췄습니다.

| 300초 생존율 (v2 → v3) | 공명술사 | 유도술사 | 각인술사 | 충격술사 |
|---|---:|---:|---:|---:|
| 도망만 다니기 (kite + learned) | 100 → 60% | 100 → 80% | 100 → 35% | 100 → 25% |
| 게임 AI (q + learned) | 100 → 77.5% | 97.5 → 20% | 82.5 → 5% | 0 → 0% |
| 제자리에 서 있기 (still + learned) | 100 → 87.5% | 97.5 → 30% | 0 → 0% | 32.5 → 0% |

도망만 다녀서는 더 이상 확실히 이길 수 없고, 위험한 시점도 뒤로 갔습니다. v2에서는 사망 288건 중 150초 이후 사망이 1건이었는데, v3에서는 695건 중 148건입니다. 회피 봇은 주로 5웨이브(120초, 이동 차단 60%) 이후에 죽습니다.

남은 문제가 있습니다.

- **게임 AI가 새 규칙을 못 따라갑니다.** 이동 정책을 8,000판, 38,000판 더 학습시켜도 나아지지 않았습니다(38,000판 정책은 유도술사 7.5%). 지금 정책이 보는 정보(가장 가까운 적 하나, 벽, 체력, 가장 가까운 경험치)로는 적 무리나 줄 이벤트를 알 수 없습니다. 주변 방향별 적 밀도 같은 관측값을 넣고 다시 학습해야 합니다. 게임에 들어 있는 정책 파일은 바꾸지 않았습니다.
- 공명술사는 가만히 서 있어도 87.5%라 아직 강합니다.
- 충격술사는 조준 방식(위 3번) 때문에 어떤 이동 방식으로도 약합니다.

v3 원본 데이터는 [data/summary.csv](data/summary.csv), [data/runs.csv](data/runs.csv)에 있습니다. 수치는 `balance.json`의 `waves`, `lineEvents`와 그 아래 값들에서 바꿀 수 있습니다.

## 다시 측정하기

```bat
balance.cmd
balance.cmd --replay 클래스 시드 [이동] [보상]
```

- 클래스: 0 공명술사, 1 유도술사, 2 각인술사, 3 충격술사
- 이동: `q`, `kite`, `still` (기본 `q`)
- 보상: `learned`, `rule`, `random` (기본 `learned`)

첫 번째 명령은 984판을 약 30초 만에 돌리고 `docs/reports/data/`의 CSV를 덮어씁니다. 두 번째 명령은 한 판을 두 번 돌려 결과가 같은지 확인한 뒤 타임라인을 `Logs/replay.txt`에 저장합니다. 측정 코드는 [Assets/Editor/BalanceLab.cs](../../Assets/Editor/BalanceLab.cs)입니다.

## 한계

- AI와 스크립트 봇의 결과라서 사람이 플레이할 때와는 다릅니다. 특히 충격술사는 사람이 적을 향해 걸어가며 쏘면 훨씬 잘 싸웁니다.
- `kite` 봇은 단순한 규칙 몇 개로 만든 봇입니다. 이 봇이 다 이긴다는 건 "도망만으로 충분하다"는 뜻이지, 최적 플레이라는 뜻은 아닙니다.
- 조합당 40판이라 승률이 50% 근처일 때 오차가 ±8%p 정도 있습니다. 0%나 100%처럼 극단적인 결과는 이 정도 오차로 뒤집히지 않습니다.
- 사망 원인 분류는 단순 규칙입니다: 벽 2칸 이내면 "몰림", 적 수가 상한(100)에 닿았으면 "물량", 접촉 거리에 4마리 이상이면 "포위", 나머지는 "소모".
